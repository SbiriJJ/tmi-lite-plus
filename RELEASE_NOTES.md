# TMI Lite+ for AI agents — 1.7

Lightweight interface for AI agents.

Status: stable release  
Release date: 3 October 2026  
Platform: Windows x64, Release configuration  
Executable version: 1.7.9772.42474 (G.T generated by the compiler)
Minimum Codex CLI: 0.157.1; tested: 0.160.0; native queue: 0.159.0 or later

## Main changes

### Included in 1.7

Version 1.7 includes the following completed work and the 1.6 Rolling features
listed below. It closes the current 1.x development state; the planned TMI 2.0
desktop backend is not part of this release.

- Optional LaTeX previews now render automatically in completed messages and
  when the rolling conversation is loaded. **Open formula** opens the same
  cached bitmap in the zoomable viewer. MicroTeX remains external and optional;
  resizing reuses previews already generated. Previews are local and do not
  alter conversation history. The common formula/image viewer now offers
  **Copy image** to the clipboard at original resolution. Full Load remains
  text-only. Mermaid/Visualize remain planned.
- Formula links now escape parentheses in the embedded TeX source. Expressions
  such as `f(x)` no longer truncate the preview or expose encoded source text.
- Fixed inline formula View/Hide corrupting subsequent text/backgrounds or
  duplicating lines: native RichEdit character offsets, padded render boundaries
  and the sorted hyperlink index now remain consistent across replacements.
  Regression checks exercise the actual main-form rendering repeatedly.

- **Duplicate (fork)** retains the source project or Unassigned while allowing
  an independent working directory. It no longer infers/creates a project from
  that directory. The server-confirmed ID, directory and project are checked
  before opening the copy and submitting its required initial prompt.
- Changing model, reasoning, service tier, approval policy or reviewer sends
  only the relevant settings. It does not replace unrelated server permissions.
  Network access changes preserve the complete confirmed workspace-write policy,
  including writable roots, read restrictions and temporary-directory settings.
- Rejected settings restore the confirmed server values in the UI; subsequent
  prompts do not silently resend rejected settings. Ordinary resumed turns use
  server settings, while new conversations keep their explicit initial defaults.

### Features carried forward from Rolling 1.6.9770.20904 — 1 October 2026

Release/Win64; tested with Codex CLI 0.159.3. Native queue operations require
CLI 0.159.0 or later. The original Rolling and stable 1.6 archives remain unchanged.

#### Project assignment preview

- The manual **Assign unassigned threads to projects...** command now previews
  thread names, working directories and destination projects before any write.
  Accept or cancel the entire list. Missing projects are created per distinct
  path only after acceptance; existing unique-root matches are reused.
- Skips agents, already assigned threads, missing working directories, ambiguous
  roots, the current user's Windows Documents folder and the Windows system
  directory, identified by Windows
  rather than its name. Documents subfolders remain eligible. Files and working
  directories are unchanged. The automatic existing-root assignment is unchanged.
- Untitled main threads display a prompt excerpt in the preview and remain
  eligible; a missing title does not imply an agent. Threads sharing a path reuse
  the same project ID, including projects created earlier in the assignment cycle.

#### Agent text directives

- Follow-up labels paste the suggested prompt into the input, with confirmation
  before replacing a draft. Sending and enqueueing remain user actions.
- File citations display clickable file names with their supplied purpose,
  preserving spaces in paths and supporting the existing file context menu.
- Unknown directives stay readable. These changes apply to completed messages
  and conversation reloads; partial streaming text remains visible until complete.
- Question links open the existing Questions panel. Conversation-name search
  is case-insensitive and includes Unassigned main threads.

#### Native prompt queue

- Added **Enqueue** and **Queue (n)** beside the prompt, with a next-message preview.
- Added an overlay panel to read, edit, remove, reorder and start pending prompts.
  Codex CLI owns and persists the queue; no local automation engine is added.
- Editing preserves attachments. Failed or unconfirmed submissions leave the
  input intact; queue errors are reported explicitly.
- No simulated pause or change to existing shortcuts. Requires CLI 0.159.0 or later.

### Rolling 1.6.9767.40409 — 28 September 2026
 
Superseded by **Rolling 1.6.9767.41769**: opening a project with no active
conversations triggers an automatic check of unassigned active threads, at most
once per application launch. Unique root matches are assigned across all
projects. Search, archived-only views and virtual groups do not trigger it.
Results and errors appear in Activity without a modal report. Empty projects
are retained; the manual command below still includes archived threads.

- Added **Assign unassigned threads to projects...** to the browser context menu.
  After confirmation, it scans active and archived main threads and assigns only
  unassigned threads whose working directory matches exactly one project root.
  Agents and existing assignments are skipped. Ambiguous and unmatched threads
  remain unassigned; no working directories or files are changed.
- The scan completes before assignments begin. The final report shows assigned,
  unmatched, ambiguous and failed counts, including server error messages.
- Repair remains read-only with respect to project assignments. Startup does not
  scan unassigned threads unless an expanded project returns an empty list.
- Verified Release/Win64 compilation, catalog protocol fixtures (pagination,
  archived threads, exclusions and errors) and main-form/UI regression checks.

### Stable 1.6

- Complete rename from Prompt Lite+ to **TMI Lite+**. Public title:
  **TMI Lite+ for AI agents**. New executable, INI, project, registry/cache/log
  names, repository and update URLs. Optional renderer: `TMILiteMath.dll`.
  No old-name lookup or automatic migration is included. Install manually
  from the new package; do not run old and new applications concurrently.

- Server-owned projects replace directory-derived project reconstruction.
  Ordinary startup reads the server project catalog; thread metadata is loaded
  when a group is expanded or a search is requested.
- A Raize grouped browser combines projects and their threads in one panel.
  It opens at startup and expands the last-used project once its list is ready
  and visible, without resuming any thread.
  **Show Threads / Show Current** describes the toggle's next action.
- Global title search with an integrated magnifier/clear button and
  **Show archived** (archived threads only). Enter searches; Esc clears while
  the field has focus. Editing and clearing restore the magnifier.
  Clicking an active thread opens it; archived entries are selected without resume.
- Row-targeted context menus provide New, Duplicate, Rename, assignment,
  Archive/Unarchive and confirmed deletion where applicable.
  Project deletion preserves its threads as unassigned. Thread deletion is
  permanent and includes spawned descendants.
- Active thread name, project and working directory are displayed separately.
  Assigning a project does not move files or change cwd. Changing cwd uses the
  server settings and applies to subsequent turns without moving existing files.
- **Project roots** lists the server roots and fills missing roots from associated
  thread directories. Add/Browse/Remove manage the list; roots used by threads
  cannot be removed. **Assign to thread** affects only the current idle thread.
  **Assign to project** can create a new named project and always preserves cwd.
- Conversation caching is optional in Config (enabled by default). Date displays
  follow Windows preferences. Longer working-directory hints and a bounded Usage
  chart tooltip improve readability without adding polling.
- Browser headings/items use normal weight; only the active project/thread names
  in the main header are bold. Working directory has a separate path line.
- Unassigned threads remain unassigned until explicitly changed; no automatic
  metadata rewrites occur during catalog loading.
- Modeless content search returns matching-message excerpts with explicit
  pagination and Stop. Opening a result uses the normal thread ownership path.
- Activity includes available server tool timing, or explicitly local elapsed
  time between events. No estimated per-tool token costs or new polling.
- MCP opens an on-demand runtime inventory of MCP servers, connectors and
  background terminals actually exposed by the server.
- Enter in other editors no longer triggers the prompt's Append button.
  Enter in Find searches; Ctrl+Enter in the prompt retains prompt submission.

## Retained features

Full Load retains its previous summary retrieval, local search and partial-stop
behavior. Normal bounded conversation loading is unchanged. Account Usage
charts, Unicode formulas, local image viewing, reset-credit information and
other preceding Rolling features remain available. Optional MicroTeX rendering
is not bundled; see MICROTEX_SETUP.md.

## Scope and verification

Generic plugin UI hosting and historical per-item timing remain deferred.
The native prompt queue is included in 1.7 and described above.
The experimental replacement for Full Load was not retained.

Grouped-control/DFM, catalog and isolated server-protocol checks passed during
development. Working-directory persistence and project deletion behavior were
tested without mutating real user threads. The user also checked the new browser.
The 1.7 Release/Win64 compilation passed. Targeted regression checks passed for
selective settings and permission preservation, fork identity/project handling,
follow-up/file-citation parsing, queue protocol and attachments, and inline
formula rendering across 30 rebuilds and three widths. Earlier UI/root-dialog
checks remain part of the development verification history.
These checks do not replace testing on every Windows or Codex configuration.
Known cosmetic limitation: the Raize embedded search button can use a lighter
background while focused. The larger glyph and search/clear actions are retained.

## Computer Use limitation with Codex CLI 0.160.0

Native OpenAI Computer Use is unavailable when TMI Lite+ 1.x is running alone
with Codex CLI **0.160.0**. The tested native backend requires a host started by
the ChatGPT desktop app. With only TMI running, `sky.list_windows()` fails before
window enumeration because the native pipe is absent:

```text
Computer Use native pipe is unavailable: failed to connect native pipe:
Impossibile trovare il file specificato. (os error 2)
```

The Computer Use plugin may still appear enabled. Neither plugin activation nor
Full Access starts the missing host. Version 1.7 supplies no independent Windows
Computer Use backend; that belongs to the separate TMI 2.0 plan. Ordinary CLI
development and independent MCP tools are not disabled by this limitation.
Computer Use remains available through its supported ChatGPT desktop host; see
[OpenAI's Computer Use documentation](https://learn.chatgpt.com/use-cases/use-your-computer-with-codex).
