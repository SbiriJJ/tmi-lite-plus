## Rolling 2.3.9798.40375 — 29 October 2026

Complete Release/Win64 bundle: `TMILitePlusBundle-2.3.9798.40375-Win64.zip`.
Published only to `rolling-2`. Stable v2.3, `stable-2`, GitHub's Latest numbered
release, all legacy 1.x channels and earlier numbered archives are unchanged.
Includes stable 2.3 and these subsequent improvements:

### Codex CLI 0.166 and maintenance

- Activity, historical item dates and live/historical diff times use the optional
  native `startedAtMs`/`completedAtMs`. Explicit `durationMs` stays authoritative.
  Missing/null fields retain older CLI behavior without extra history requests.
- A label beside Memory shows the CLI version actually running the selected
  work; with no selected work, it describes the thread-browser process. Unknown
  or disconnected versions show `Codex --`, never an inferred installed maximum.
- The host captures executable and version together for start, reconnect and
  scheduling. Stale executable hints from a frontend cannot select an older CLI
  after Maintenance. A local version-only probe is bounded to three seconds;
  failure is diagnostic and does not block an otherwise usable app-server path.
- CLI update availability now follows the official installer release channel,
  not GitHub's potentially earlier publication. GitHub supplies notes for that
  exact version. Installation/update passes the displayed release explicitly
  with `-Release` and verifies installer/current before changing TMI's selection
  or cleaning the cache. Cleanup retains the previous selection until commit.
- CLI Setup adds **Network diagnostics**, available for a selected CLI 0.166+
  only on request. `doctor --network-only --no-color --ascii` streams into the
  existing output memo with a 60-second timeout; it does not perform database or
  MCP scans, install anything, save settings or refresh releases.
- Compatible launches disable startup marketplace recommendation prefetch.
  Installed plugins, Browser Tools and later explicit discovery remain available;
  this is not an offline mode. Older CLI selections do not receive the new flag.
- `policyCapacityUnavailable` has a distinct **Capacity unavailable** caption.
  Native `willRetry` remains authoritative. Closing/resume rejection is covered
  by regression checks; no automatic retry or fragile error-message matching was
  introduced. Codex's own token/context corrections are not claimed as a change
  to subscription billing.
- CLI Setup's read-only edits and retention spinners, including their disabled
  states and arrow buttons, now use the shared dark palette.

### Review and recovery corrections

- Unexpected process-reader termination invalidates the dead resident process's
  turn/requests coherently. Explicit reconnect replaces it without replaying
  prompts; Maintenance preserves the reader-failure diagnostic.
- Disabling a schedule also prevents its already queued jobs from dispatching.
  Submission occurs outside the schedule lock, with coherent missed/log state.
- A first prompt is retained when opening a New conversation fails; asynchronous
  failure does not overwrite a later draft.
- The existing Download context-menu operation becomes **Cancel download** while
  busy. Native file and HTTP copies support cancellation, protect the destination
  until successful completion and clean up temporary output. Frontend closure
  cancels/joins under its existing five-second shutdown deadline.

### Verification

All four package binaries are Release Win64, version family 2.3 / IPC 16; their
individual compiler-generated G.T components need not be identical. Focused
fixtures cover timestamp null/legacy/delayed delivery and native duration,
history/diff dates, actual child-process launch arguments, version selection,
resident failures/closing/reconnect, browser toggles, response presentation,
bounded locator probes, hidden designer controls, prompt keyboard handling,
scheduling and download cancellation. The selected installed Codex version and
official-channel lookup were checked in read-only mode. Network diagnostics
itself was not run against a real account during these offline fixture checks.
These checks are not exhaustive certification of Codex 0.166 or every provider.

## Version 2.3 — stable, 28 October 2026

Install the complete matching four-executable
`TMILitePlusBundle-2.3.9797.42811-Win64.zip`. Version 2.3 advances `stable-2` and
is GitHub's Latest numbered release. The independent `rolling-2` package,
legacy 1.x assets/endpoints and all earlier numbered ZIPs remain unchanged.
This stable release includes the improvements previously published on Rolling

### Conversation, graphics and notes

- Visualize widgets are interactive directly inside the conversation, including
  tabs, tooltips and expandable sources. Space follows DOM height changes.
  Mermaid adds local zoom/reset, drag-to-pan and Ctrl+wheel zoom. Offscreen views
  suspend and resume with state intact; repeated occurrences keep separate state.
  The configurable history-preview budget still limits automatic reload work.
- Local Notes combines notes from the project's working directories, oldest
  first. Each note is a manually editable UTF-8 Markdown file in its directory's
  `.tmi-notes` folder. New notes target the selected CWD. Priority/Completed,
  explicit Edit, conflict-aware autosave, dirty markers and <Prompt are included.
- Sample displays temporary tool-free answers and available usage counts in the
  conversation, shows progress/cancellation in Activity, and never alters native
  history or main token baselines. Its 4,000-byte UTF-8 prompt limit has a visible
  byte counter; ordinary prompts are not restricted by that Sample limit.
- Restored autoscroll/Full Load access, retained the selected thread after manual
  Disconnect, and fixed closing/reconnection presentation. Intermediate persisted
  messages remain available even when a final reply is absent.

### Shared state, diagnostics and live file changes

- Host-owned Auto switch optionally moves focus between existing non-minimized
  frontends, prioritizing questions, approvals and idle work. It supports a
  cancellable deferred wait and one shared startup preference, default Disabled.
- Task completion, permission/input requests and errors use native taskbar
  attention. Independent tray badges distinguish Working, Codex response warnings
  and user decisions; a red perimeter remains the local-failure indicator.
  Codex busy/retry/capacity messages are not mislabelled as local TMI failures.
- Memory opens the native shared summary in a nonmodal read-only viewer with
  Lock, Refresh and forward/backward search. Configuration exposes Enable
  Memories, Use memories and automatic background-generation permission through
  native version-guarded configuration writes. This is not an active-context
  viewer, and Refresh does not generate memories.
- Native Codex diagnostic ZIP export requires explicit log/conversation choices
  and a new local destination. TMI does not upload the archive.
- Compatible IDE Bridge edits populate Changed Files and compact Activity
  summaries during live work. Immutable patch artifacts are loaded only on
  request and size/hash checked. Save-only reports do not erase earlier edits;
  Bridge metadata/diffs are not restored on history reload.

### CLI installation and recovery

- Local CLI readiness is published before optional version/network/startup
  inspection. Executable probes, pipe reads and advisory checks are bounded;
  optional check failures no longer hold the service offline.
- CLI Setup can select an already installed standalone version without
  uninstalling the current one or changing the system Codex command. Successful
  install/update selects the updated current executable automatically.
- Configurable previous-minor count and minimum release age control cleanup.
  Publication dates are read in memory; unknown dates retain packages and report
  a warning. No new installation-date ledger is stored.
- Update availability compares the latest public version with the newest
  installed version, not the selected rollback. The selected runtime is unchanged.
- Accepting an authoritative host CLI path no longer generates a false
  shared-settings conflict when Configuration saves before Restart and Update.
  Real concurrent settings conflicts remain protected.
- Obsolete thread/default models resolve only from the advertised catalog.
  If both are unavailable, the newest numeric model version is selected, keeping
  server order for ties. A supported manual selection can resume that same
  existing thread rather than leaving Send permanently disabled. `config.toml`
  is not rewritten.
- OpenAI browser/Node tools stay disabled by default for TMI-started sessions.
  Browser Tools can be enabled/disabled temporarily for an idle thread, reopening
  only that work. The saved Configuration choice remains the startup default.
- Worktime consumes only active-thread Limits notifications; idle polling updates
  the indicator, not the statistics. Reset-time changes below 60 seconds no
  longer split cycles even when remaining quota rises to 99/100%. Existing
  measurements are not silently merged or rewritten.

### Verification and limitations

All four binaries are Release Win64; G.T file-version components are compiler
generated. Focused isolated model/settings/maintenance/worktime/native-contract
checks and practical installed-version/desktop tests support these changes.
Codex 0.164.0 was the primary runtime; selected-version and focused 0.165.0
checks are not exhaustive certification of every capability or future CLI.

Fresh installation still requires separate Codex authentication, for example
`codex login`; a native login screen is not yet implemented in TMI. Some native
secondary-dialog controls can retain Windows light styling; the separate theme
audit is not included in this release.

### Scheduling, recovery and live feedback

- Worktime no longer splits or stalls on small reset-deadline estimates. It
  accepts new quota deadlines in either direction, restores the known quota at

- Queue now covers the conversation area, with a bold yellow title, Close at

### Host-owned Worktime statistics

- The host sums the elapsed Working time of all resident threads, including
  detached works. Approval/input waits, Idle and connection preparation do not
  count; two threads working one minute contribute two minutes.
- Every whole 1% decrease in the shared main subscription limit records a
  sample. A multi-point decrease distributes accumulated time equally between
  its points. Other/plugin quota buckets do not drive this statistic.
- Any increase in remaining percentage starts a new cycle, even below 100%.
  Current and previous cycles are retained in the Windows registry.
- Click Worktime last (1%) / current, beside Poll above the compact Usage
  buttons, to open the nonmodal Current / Past / All graph. Unobserved bands are
  distinct from measured zero. No graph is created until requested.
- This is an approximate local statistic, not billing data or a measurement of
  use on other computers or online. Existing Usage and Thread usage stay
  unchanged. Real collection starts after the updated host is restarted.

### Changed Files and diff selection

- Changed Files stays enabled without first sending a prompt, including while
  disconnected. Diff is the first context-menu command and Open the second;
  double-click still opens the file.
- The nonmodal diff viewer supports Ctrl/Shift multiselection. Opening it from
  Changed Files or Activity selects the latest edit directly, including all
  edits with the same timestamp to the second.

### Read-only agent inspection

- Agent conversation snapshots use `thread/read` through the parent's resident

## Version 2.0 — stable, 9 October 2026

Stable Windows executable version: 2.0.9778.29506.

### Resident backend and independent work

- TMIHost is a resident tray backend; each work has an independent Codex
  app-server process. Switching conversation or closing a frontend detaches
  presentation without cancelling work. Reattachment reuses that resident
  writer instead of issuing a conflicting second resume.
- Multiple frontends operate independently. Sessions and tray entries show
  resident titles, project, directory, state and pending requests.
- Approvals and Questions belong to the owning frontend. Requests remain
  pending when it is closed; tray/notification selection opens the right thread.
  The host never silently accepts a pending decision or opens thread forms.
- Tray working/error indicators remain part of the normal status flow. Idle
  taskbar titles omit `[I]`. Left-click routes to existing/pending work; the
  menu's Open TMI Lite+ always creates a new unselected frontend.
- Coordinated shutdown has a shared five-second deadline. Idle host exit does
  not require confirmation. Observed/controlled applications are not terminated.

### Independent Computer Use

- TMI's own `tmi_desktop` MCP backend replaces dependence on the ChatGPT desktop
  app's private computer-use host. It supports bounded window discovery,
  text/PNG observations, application launch and window/control actions.
- Read/control permissions are separate and revocable. A global-read switch
  permits authorized passive reads without granting input or launch. Permanent
  application grants are scoped to executable paths.
- Native Win32 observations and direct window-message actions support covered
  controls without TMI bringing the target to the foreground. UIA semantic
  actions and physical mouse/keyboard input remain explicit alternatives with
  their own foreground requirements; there is no hidden fallback or retry
  after uncertain mutation.
- All monitors show visible blue warnings for passive reads and priority red
  for control. The non-blinking, mouse-avoiding banner says
  "Codex is using your computer (ESC to interrupt)" and does not steal focus.
- Physical ESC interrupts the current operation and releases held synthetic
  input, returning `user_interrupted`. It does not disable later requests.
- Compact native/UIA observations, targeted control reads, output limits and
  cropped/resized PNGs avoid unnecessary data. Native identities stay private.
  Explicit cancellation, stale-target and unavailable-capture results replace
  unpredictable retries.

### Host-owned maintenance and updates

- Codex CLI detection, startup/six-hour checks and shared CLI status are
  host-owned. Frontends do not duplicate the version-check workflow.
- CLI Setup is the separate, on-demand TMIMaintenance application, also usable
  without host/frontend. It streams progressive command output and exits on close.
- Opening maintenance suspends idle Codex connections and keeps drafts/frontends
  intact; closing it reconnects the same works without replaying prompts.
  Working, opening or waiting work prevents unsafe maintenance.
- Local updates support the matching multi-file 2.0 bundle. Install matching
  executables together; older protocol peers are rejected rather than sent

## Computer Use limitation with Codex CLI 0.160.0

Native OpenAI Computer Use is unavailable when TMI Lite+ 1.x is running alone
with Codex CLI **0.160.0**. The tested native backend requires a host started by
the ChatGPT desktop app. With only TMI running, `sky.list_windows()` fails before
window enumeration because the native pipe is absent:

```text
Computer Use native pipe is unavailable: failed to connect native pipe:
Impossibile trovare il file specificato. (os error 2)
```

The Computer Use plugin may still appear enabled. Neither plugin activation nor
Full Access starts the missing host. Version 1.7 supplies no independent Windows
Computer Use backend; that belongs to the separate TMI 2.0 plan. Ordinary CLI
development and independent MCP tools are not disabled by this limitation.
Computer Use remains available through its supported ChatGPT desktop host; see
[OpenAI's Computer Use documentation](https://learn.chatgpt.com/use-cases/use-your-computer-with-codex).
